01 — El problema

DevTools no sabe nada de tu proyecto

Ajustar un componente a mano en el navegador funciona, pero tiene fricción constante: el panel Elements muestra todo el árbol sin distinguir tu componente del wrapper del framework, cada valor que tocás en Styles desaparece en el próximo refresh o re-render, y si el resultado te convenció, tenés que traducirlo a mano al archivo fuente — adivinando cuál es, si el proyecto no te lo dice.

Ese ciclo se repite cada vez que abrís la pestaña: seleccionar, tocar, perder, repetir. En una sesión larga de ajuste fino de layout, esa fricción se vuelve el costo real del trabajo.

03 — Funciones

Pensada para tocar, no solo para mirar

Selección persistente

Un interruptor ON/OFF, no un botón de un solo uso. El elemento fijado, la vista activa y el scroll del panel sobreviven a cualquier recarga completa.

Consciente de Tailwind

Si el proyecto usa Tailwind, elegís directo entre la escala real de espaciado y tipografía del proyecto — nunca un valor inventado.

Avisos de valores negativos

Un margin negativo puede descuadrar todo un layout sin avisar. Lens-SK lo marca en la fila y en el diagrama box-model.

⚠ -20px detectado

Ocultar, clonar y señalar

Ocultá un bloque con cascada visual a sus hijos, duplicalo para probar un layout con más ítems, o señalalo en la página sin salir del árbol ni depender de hover.

Árbol HTML editable

El DOM completo como un editor de código, con clases y texto editables por nodo, y un ojo por fila para ocultar sin perder de vista la estructura.

Modo IA (opcional)

Con una sesión de Claude Code activa escuchando del otro lado, aparecen 🪄 Pedir cambio y 📤 Aplicar a archivos reales. Sin esa sesión activa, ni se muestran — no es una dependencia nueva, es una capa opcional encima.

04 — Instalación

Sin configuración. Sin dependencias nuevas en producción.

Auto-inyectada en modo desarrollo, excluida del build de producción por un paso de compilación — no por un chequeo en runtime que podría fallar.

npmdevDependency
# instalar
npm install -D lens-sk

# en tu entry point de desarrollo
import "lens-sk/auto";
Se auto-inyecta solo en NODE_ENV=development. El build de producción no la incluye.
CDNscript tag
<!-- cualquier página, cualquier stack -->
<script src="https://cdn.lens-sk.dev/toolbar.js"></script>
Sin build step. Útil para WordPress/PHP renderizado o un HTML estático.
